# Deployment findings

- Prisma 6.5.0 client generation does not prove the installed CLI schema engine is bundled. Build the installed CLI tools explicitly, then execute schema/client engine checks offline as an unprivileged user before image publication. Startup uses the pinned installed CLI, not `pnpm dlx`.
- Coolify generated per-service `env_file: .env` paths resolve from the project directory. Use the checkout root consistently; a nested deployment directory fails even when the CLI environment file is absolute.
- A candidate-only registry token must not be marked runtime: Coolify can inject its generated runtime environment file into every service. Retain registry credentials outside app/build injection and do not overwrite a shared server registry login.
- Upstream session middleware can create a missing organization API key during `GET /user/self`. Do not describe that generic session check as read-only; prove the required state or use a read-only database role for a separate preserved-session test.
- GNU `timeout` needs a bounded `--kill-after` to terminate a TERM-ignoring Docker client. Track and verify only the temporary helper’s exact container ID during cleanup.
- Compose profiles can be enabled by inherited `COMPOSE_PROFILES`, including a selected dotenv file. Infrastructure-only startup explicitly clears that environment value; publisher selection requires both an explicit activation flag and production runtime intent.
- Coolify helper 1.0.19 uses BusyBox timeout, not GNU coreutils. Both support `timeout -k SECONDS`; BusyBox rejects GNU’s long `--kill-after` option. Test shell utilities in the actual helper image, not only on the host.
- Coolify's temporary source checkout is not proof that a relative bind exists on the Docker host. Main's candidate deployment showed an empty dynamic-config host directory hiding the image defaults. Production Temporal 1.28.1 now uses its built-in `config/dynamicconfig/docker.yaml` without a mount; source and preparation checks reject restoring that dependency.
- Source `internal: true` networks do not prove deployed isolation: Coolify also attached its external candidate network to all seven infrastructure services. Preparation strips only the recognized external attachment from infrastructure, retains exact source bindings and publisher routing, and rejects unknown network shapes. Check actual container attachments after deployment.
- PM2 supervising pnpm → dotenv → Node chains left original Node children orphaned after restart in the main session's isolated test. Old children still served HTTP 200 while replacements looped on occupied ports. Production now uses foreground `pm2-runtime` with direct Node entrypoints after the normal guarded schema push; restart acceptance must inspect child/port ownership and stable restart counts, not only HTTP responses.

- Correlating Page-save diagnostics by an intermediate integration ID mixes two tabs that upsert the same member. Preserve a per-attempt server-validated binding through the picker; keep it independent of dashboard lookup and authorization. Regression must use two callbacks sharing one integration.
- Offline TypeScript transpilation on the laptop is not the pinned-runtime build. Run diagnostic safety tests inside the actual Node22/TypeScript5.5 image with source overlays or the built commit image, network disabled and a read-only filesystem.

- Post analytics receive no inherent media-format proof from a native post ID. Carry optional saved dispatch context from the org-scoped Post lookup through the provider interface and standalone delegation; unknown media/settings remain unproven. Validate explicit counter presence before attaching provenance; a missing LinkedIn total is not zero.

- Facebook Page feed insights do not supply every interaction counter. Count-only LIKE-filtered reactions and stream-comment summaries returned explicit0 under the existing Page credential; shares was omitted and must remain unavailable. Keep vendor-filter definitions explicit, validate exact node identity/empty actor arrays, and isolate summary failures from insights. A zero-only transport probe is not certification of CARE/reply inclusion or ordinary editorial Results ingestion.

- Closed registration in upstream is not unconditional: canRegister permits an empty organization store and GENERIC identities. Unknown Google callbacks also return a registration token before the final guarded creation path. Keep existing provider lookup before closure, refuse unknown callbacks before returning that token, and retain callback routing for existing users. Blocking every provider query at the registration page would also block staff Google login. This is a source finding; live staff access needs separate acceptance after release.

- Cache only the dependency target across hosted runners; whole-build mode=max can duplicate large application layers. Keep the fetched store outside /app and assert its absence in the runtime image. A copied public configuration guard must reject comment payloads as well as unknown keys: ignored comments are still bytes exported by COPY. Actual cache hits and timings remain separate from source review.

- With pnpm10.6.1/hoisted fetch, ignored dependency scripts remain pending even when a later frozen offline install exits0 and runs project hooks. A real approved dependency fixture caught this; explicit named rebuild respects the allowlist and avoids rerunning project hooks. Require a real final-image native render, not package presence or root-hook success. Canvas needed its own narrow build approval; a missing binding does not prove missing system libraries.

- The deployed Temporal SDK decodes an empty pagination token as an ordinary array, whereas synthetic fixtures used a Buffer. Read-only workflow probes must accept both empty byte representations and reject nonempty/malformed tokens; verify the actual stdin entry and a live metadata read. Zero pending activities does not mean no durable timers or future email side effects.

- Cold acquisition must quiesce every persistent-state writer, including clients such as Temporal, rather than blindly terminating stateless dashboards. Keep zero-mount UI/admin identities and start times pinned while their backing writer is stopped. An observed shutdown exit2 is not a clean-stop exemption; the six-writer backup retains strict exit checks and actual restore proof remains separate from tar checksums.

- MemAvailable already excludes running clones' resident anonymous/shared memory. Keep initial full-peak admission and the operating reserve; later credit only lower sampled anon+shmem from exact guarded owned cgroup-v2 identities. Never credit whole limits, file cache or kernel/slab. Check PID/start, membership, ownership and caps before/after; unknown identity is a refusal, not free capacity.
- Read-only Elasticsearch startup still needs writable private configuration for its keystore, as well as its early JVM log sink. Copy only baked config into nonroot-owned bounded tmpfs, reject declarative plugin installation, and control JVM heap/temp/error/log options. A later logging reset does not prevent an earlier file sink from opening.
- Docker inherits image labels into containers and can omit the optional image Labels field when it is empty. Compare the complete immutable-image-plus-run label map; reject reserved ownership collisions and altered or extra labels. Model the actual pinned images before executing a fresh recovery family, rather than assuming synthetic inspection shapes match the host.

- When a disposable recovery stack narrowly misses admission, an explicitly approved reduction of hard per-role caps can reduce demand without reducing the operating reserve or relaxing the memory assertion. Bind the same caps in plan/create/inspect/cgroup checks. Warm original-service samples are not cold-start peaks; normal isolated startup and reads must still prove the tighter allocation works.

- An available probe on an already-running original does not prove a constrained recovered copy can become ready in a shorter budget. Align the bounded ES readiness window with accepted engine evidence while retaining CPU/memory and health assertions; measure only sanitized successful wait duration. A timeout alone does not establish the exact startup cause or authorize retrying a used family.
